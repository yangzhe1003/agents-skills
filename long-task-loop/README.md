# long-task-loop

让 agent 在当前会话内持续推进长任务，并用磁盘检查点支持中断续做。

## 使用

技能位于用户级目录 `~/.agents/skills/long-task-loop/`，可供多个项目使用。新建会话后，在技能列表确认 `long-task-loop` 已被发现，再输入：

```text
/long-task-loop 完成订单导出功能。验收条件：支持 CSV 下载，相关测试及构建通过。在授权范围内持续执行，不要每完成一步就停下来问我。
```

也可以显式限定预算：

```text
/long-task-loop 修复当前项目所有类型错误，最多执行 15 轮，不改变业务行为，以项目类型检查通过为验收条件。
```

续做：

```text
/long-task-loop 继续 .agent-tasks/order-export/STATE.md 中的任务，先核实中断时的执行结果。
```

若当前会话还未刷新技能列表，可明确让 agent 读取此目录的 `SKILL.md` 并按其执行。文件已安装不等于已验证宿主热加载。

## 执行约定

创建任务前，先完成需求拆解：明确目标与范围，列出具体行为和边界情况，将每项需求映射到有产物、依赖、验收条件及验证方式的执行项草案，并检查覆盖是否完整。先展示拆解，再创建任务并进入循环。影响范围或验收的歧义未解决时，停在需求阶段；需求已经明确且获得实施授权时，无需再额外审批一次。

每轮选取一个可验收的小目标，执行、验证并保存状态。验收未完成且仍可推进时继续工作。默认每次最多 30 轮，用户可以覆盖；连续 3 轮无进展时换策略，换策略后再连续 3 轮无进展则阻塞该项，继续其他可做项。

检查点写入**目标项目**的 `.agent-tasks/<task-id>/STATE.md`。它记录目标、授权、任务清单、验证证据、正在运行的任务和精确下一步。预算耗尽写 `paused`，缺少必要输入写 `blocked`，只有所有必需验收通过才写 `completed`。

## 能力边界

这是技能，不是进程守护程序。它指导正在运行的 agent 持续执行，也支持下一次被调用时从磁盘恢复；不会在 ZCode 退出或机器重启后自行唤醒。真正跨进程无人值守需要另配宿主运行器、hook 或外部循环。本次没有安装这些机制，没有配置定时任务，也没有开启跳过权限检查。
